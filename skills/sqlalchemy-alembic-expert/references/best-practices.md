## 1. Models — Declarative Style (SQLAlchemy 2.x)

### 1.1 Use `DeclarativeBase` + `mapped_column()` + `Mapped[]`

SQLAlchemy 2.0 made a full break from the legacy `declarative_base()` / `Column()` approach. The new style uses `DeclarativeBase` with PEP 484–compatible type annotations.

```python
# ❌ Old-style (SQLAlchemy 1.x / 2.0 legacy)
from sqlalchemy.ext.declarative import declarative_base
Base = declarative_base()

class User(Base):
    __tablename__ = "user"
    id = Column(Integer, primary_key=True)
    name = Column(String(255), nullable=False)

# ✅ New-style (SQLAlchemy 2.x)
from sqlalchemy.orm import DeclarativeBase, Mapped, mapped_column

class Base(DeclarativeBase):
    pass

class User(Base):
    __tablename__ = "user"
    id: Mapped[int] = mapped_column(primary_key=True)
    name: Mapped[str] = mapped_column(String(255))
    email: Mapped[str | None] = mapped_column(String(255))  # nullable = Optional
```

`Mapped[T]` gives mypy and pyright full type inference — `user.name` is `str`, not `Any`. The old-style plugin-based mypy support is deprecated.

### 1.2 Centralise String Lengths

Define string lengths as named constants rather than magic numbers scattered across the model file:

```python
LEN = {
    "NAME": 255,
    "EMAIL": 255,
    "ROLE": 16,
}

class User(Base):
    name: Mapped[str] = mapped_column(String(LEN["NAME"]))
```

### 1.3 Constraint Naming Convention

Always pass a `naming_convention` to `MetaData` so autogenerated constraint names are deterministic and portable across databases. Without it, PostgreSQL names constraints with internal hash-based names that differ between environments and break `alembic --autogenerate`.

```python
from sqlalchemy import MetaData

NAMING_CONVENTION = {
    "ix": "ix_%(column_0_label)s",
    "uq": "uq_%(table_name)s_%(column_0_name)s",
    "ck": "ck_%(table_name)s_%(constraint_name)s",
    "fk": "fk_%(table_name)s_%(column_0_name)s_%(referred_table_name)s",
    "pk": "pk_%(table_name)s",
}

class Base(DeclarativeBase):
    metadata = MetaData(naming_convention=NAMING_CONVENTION)
```

[Source: Alembic docs — The Importance of Naming Constraints](https://alembic.sqlalchemy.org/en/latest/naming.html)

### 1.4 Mixin Classes for Shared Columns

Pull repeated fields (`created_at`, `updated_at`, `id`) into mixin classes rather than copy-pasting:

```python
from datetime import datetime
from sqlalchemy import func
from sqlalchemy.orm import Mapped, mapped_column

class TimestampMixin:
    created_at: Mapped[datetime] = mapped_column(
        DateTime(timezone=True), server_default=func.now(), nullable=False
    )
    updated_at: Mapped[datetime] = mapped_column(
        DateTime(timezone=True),
        server_default=func.now(),
        onupdate=func.now(),
        nullable=False,
    )

class WithID:
    id: Mapped[int] = mapped_column(primary_key=True, autoincrement=True)

class User(WithID, TimestampMixin, Base):
    __tablename__ = "user"
    ...
```

### 1.5 Enums — Use Python `StrEnum`

Use Python's `StrEnum` (Python 3.11+) as the source of truth for DB enum values. SQLAlchemy maps it transparently:

```python
from enum import StrEnum
from sqlalchemy import Enum as SAEnum

class MessageRole(StrEnum):
    USER = "user"
    ASSISTANT = "assistant"

class Message(Base):
    role: Mapped[MessageRole] = mapped_column(SAEnum(MessageRole, name="message_role"))
```

## 2. Session Management

### 2.1 One Session Per Unit of Work

A `Session` / `AsyncSession` is **not** thread-safe and should never be shared across concurrent tasks. Each request, worker task, or background job must get its own session.

```python
# ✅ Correct — session scoped to function
async def process_user(user_id: int) -> None:
    async with async_session_factory() as session:
        user = await session.get(User, user_id)
        user.active = True
        await session.commit()

# ❌ Wrong — global session shared across tasks
session = AsyncSession(engine)  # do not do this
```

### 2.2 `expire_on_commit=False` for Async

In async code, set `expire_on_commit=False` on the session factory. After `commit()`, SQLAlchemy normally expires all attributes — in sync code the next access triggers a lazy load, but in async code that raises `MissingGreenlet` because there is no implicit I/O.

```python
async_session = async_sessionmaker(engine, expire_on_commit=False)
```

[Source: SQLAlchemy docs — Preventing Implicit IO when Using AsyncSession](https://docs.sqlalchemy.org/en/20/orm/extensions/asyncio.html)

### 2.3 Context Manager Pattern

Always use sessions as async context managers. This guarantees `close()` even on exception:

```python
async def get_user(user_id: int) -> User | None:
    async with async_session_factory() as session:
        return await session.get(User, user_id)
```

### 2.4 Transaction Boundaries — Be Explicit

Wrap multi-step writes inside `async with session.begin()`:

```python
async with async_session_factory() as session:
    async with session.begin():
        session.add(user)
        session.add(profile)
        # commit happens automatically on __aexit__
        # rollback on exception
```

## 3. Async Engine & Connection Pooling

### 3.1 Production: `AsyncAdaptedQueuePool` with Tuned Sizes

For a long-running service (NATS worker, FastAPI app):

```python
from sqlalchemy.ext.asyncio import create_async_engine

engine = create_async_engine(
    dsn,
    echo=False,               # True only for debug; logs every SQL statement
    pool_pre_ping=True,       # checks connection health before using it
    pool_size=20,             # base pool size
    max_overflow=0,           # do not allow extra connections beyond pool_size
    pool_recycle=3600,        # recycle connections every hour (avoids stale TCP)
)
```

`pool_pre_ping=True` is critical in production — it prevents `connection already closed` errors after a PostgreSQL restart or firewall timeout.

[Source: SQLAlchemy docs — Connection Pooling](https://docs.sqlalchemy.org/en/20/core/pooling.html)

### 3.2 Migrations & Tests: `NullPool`

For Alembic migrations and test suites, always use `NullPool`. Migrations run once and don't benefit from pooling; tests need full connection teardown between runs:

```python
from sqlalchemy import pool
connectable = async_engine_from_config(
    config,
    prefix="sqlalchemy.",
    poolclass=pool.NullPool,  # no connection reuse — critical for tests
)
```

### 3.3 Serverless / Lambda: `NullPool` Always

In serverless environments (AWS Lambda, Vercel Functions), use `NullPool`. Pooling makes no sense — each function invocation is ephemeral. Using `QueuePool` in serverless leaks connections.

### 3.4 `asyncpg` Statement Cache for PgBouncer

When using `asyncpg` and PgBouncer in `transaction` pooling mode, disable the prepared-statement cache — PgBouncer doesn't support it:

```python
connect_args={
    "statement_cache_size": 0,
    "prepared_statement_cache_size": 0,
}
```

## 4. Query Patterns & Performance

### 4.1 Prefer `select()` Over Session Query API

The legacy `session.query(Model)` API is removed in SQLAlchemy 2.0. Use `select()`:

```python
from sqlalchemy import select

stmt = select(User).where(User.active.is_(True)).order_by(User.created_at.desc())
result = await session.execute(stmt)
users = result.scalars().all()
```

### 4.2 Eager Loading to Kill N+1

Lazy loading is disabled in async SQLAlchemy by default (raises `MissingGreenlet`). Always specify a loading strategy:

| Strategy | SQL emitted | Best for |
|---|---|---|
| `selectinload` | SELECT … WHERE id IN (…) | large collections, one-to-many |
| `joinedload` | JOIN | single objects, many-to-one |
| `subqueryload` | correlated subquery | legacy; prefer `selectinload` |
| `contains_eager` | explicit JOIN + annotate | when you write the JOIN yourself |

```python
from sqlalchemy.orm import selectinload, joinedload

stmt = (
    select(User)
    .options(selectinload(User.messages).joinedload(Message.chat))
    .where(User.active.is_(True))
)
```

### 4.3 Bulk Inserts / Upserts

For high-throughput inserts, use `insert()` with `on_conflict_do_update()` (PostgreSQL):

```python
from sqlalchemy.dialects.postgresql import insert as pg_insert

stmt = pg_insert(MyModel).values(rows)
stmt = stmt.on_conflict_do_update(
    index_elements=["user_id", "tenant_id"],
    set_={
        "data": stmt.excluded.data,
        "updated_at": func.now(),
    },
)
await session.execute(stmt)
```

### 4.4 Index Design

- Put indexes on every foreign key and every column used in `WHERE` clauses.
- Composite indexes beat two single-column indexes when queries filter both columns together.
- `created_at` used in time-windowed queries **must** have an index — a full-table scan is not acceptable.

```python
class Message(Base):
    __tablename__ = "message"
    __table_args__ = (
        Index("ix_message_chat_id_created_at", "chat_id", "created_at"),
        Index("ix_message_created_at", "created_at"),
    )
```

### 4.5 `text()` for Raw SQL

When you need raw SQL (complex CTEs, window functions), wrap it in `text()` and use bound parameters — never f-string SQL:

```python
# ✅ Safe — parameterised
stmt = text("SELECT MAX(updated_at) FROM hpe_user_profile WHERE user_id = :uid")
result = await session.execute(stmt, {"uid": user_id})

# ❌ SQL injection risk
stmt = text(f"SELECT * FROM user WHERE name = '{name}'")
```

### 4.6 `scalars()` vs `scalar()` vs `all()`

```python
result = await session.execute(select(User))

result.scalars().all()      # list[User] — multiple rows
result.scalar_one()         # User — exactly one row, raises on 0 or 2+
result.scalar_one_or_none() # User | None — 0 or 1 row
result.all()                # list[Row] — tuples, not ORM objects
```

## 5. DAL / Repository Pattern

### 5.1 Generic `BaseDAL` with Type Safety

```python
from typing import Generic, TypeVar, Type
from sqlalchemy.ext.asyncio import AsyncSession

Model = TypeVar("Model", bound=Base)

class BaseDAL(Generic[Model]):
    model: Type[Model]

    def __init__(self, session: AsyncSession) -> None:
        self.session = session

    async def get(self, pk: int) -> Model | None:
        return await self.session.get(self.model, pk)

class UserDAL(BaseDAL[User]):
    model = User
```

### 5.2 Error Wrapping Decorator

Wrap database operations in a decorator that converts `IntegrityError` / `SQLAlchemyError` into domain exceptions:

```python
def db_error_handler(func):
    @functools.wraps(func)
    async def wrapper(self, *args, **kwargs):
        try:
            return await func(self, *args, **kwargs)
        except IntegrityError as exc:
            if getattr(exc.orig, "pgcode", "") == "23505":
                raise UniqueConstraintError() from exc
            raise DBIntegrityError() from exc
        except SQLAlchemyError as exc:
            raise DBIntegrityError() from exc
    return wrapper
```

### 5.3 `rowcount` Type Issue

The static type of `session.execute()` is `Result[Any]`, but the runtime object is `CursorResult` which has `.rowcount`. Centralise the cast:

```python
from typing import Any, cast
from sqlalchemy.engine import CursorResult

def _rowcount(result: Any) -> int:
    """Return DML rowcount from a SQLAlchemy execute result."""
    return cast(CursorResult[Any], result).rowcount
```

## 6. Alembic Migrations

### 6.1 `env.py` — Async Pattern

```python
import asyncio
from sqlalchemy import pool
from sqlalchemy.ext.asyncio import async_engine_from_config
from alembic import context

# MUST import all models
from myapp.models import Base
import myapp.extra_models  # noqa: F401
target_metadata = Base.metadata

def do_run_migrations(connection):
    context.configure(connection=connection, target_metadata=target_metadata)
    with context.begin_transaction():
        context.run_migrations()

async def run_async_migrations():
    connectable = async_engine_from_config(
        config.get_section(config.config_ini_section, {}),
        prefix="sqlalchemy.",
        poolclass=pool.NullPool,
    )
    async with connectable.connect() as conn:
        await conn.run_sync(do_run_migrations)
    await connectable.dispose()

def run_migrations_online():
    asyncio.run(run_async_migrations())
```

### 6.2 Always Import All Models in `env.py`

`autogenerate` only detects tables that are imported before it runs. Missing imports → missing migrations → schema drift.

### 6.3 Naming Conventions

Set `naming_convention` on `MetaData` before `autogenerate`. Without it, Alembic generates migrations with database-assigned names that break `alembic downgrade`.

### 6.4 Migration File Hygiene

- **Never edit a migration that has already been applied.** Create a new one.
- **Always review autogenerated migrations** — `autogenerate` cannot detect: stored procedures, triggers, partial indexes, data migrations.
- **Include `downgrade()`** for every migration.
- **Keep migrations atomic** — one logical schema change per file.

### 6.5 CI/CD — Run `alembic check`

```yaml
- name: Check migrations are up to date
  run: alembic check
```

### 6.6 Branching & Merging

```bash
alembic merge -m "merge heads" head1_hash head2_hash
```

### 6.7 Non-Nullable Column Additions

```python
# Step 1: Add nullable column
op.add_column("user", sa.Column("tier", sa.String(32), nullable=True))
# Step 2: Backfill data
op.execute("UPDATE user SET tier = 'standard' WHERE tier IS NULL")
# Step 3: Apply NOT NULL constraint
op.alter_column("user", "tier", nullable=False)
```

### 6.8 Zero-Downtime Migration Table

| Operation | Safe? | Strategy |
|---|---|---|
| Add nullable column | ✅ | Direct |
| Add NOT NULL column | ⚠️ | Backfill + set default first |
| Drop column | ⚠️ | Remove from code first, then migrate |
| Rename column | ❌ | Add new column, dual-write, then drop old |
| Add index CONCURRENTLY | ✅ | PostgreSQL only; `op.execute()` with raw SQL |

## 7. Testing Strategy

### 7.1 Test Database Lifecycle

```python
def pytest_sessionstart(session):
    create_database(sync_db_uri_test)
    subprocess.run(["alembic", "-c", alembic_ini_path, "upgrade", "head"], check=True)
    asyncio.run(populate_test_database())

def pytest_sessionfinish(session, exitstatus):
    close_all_sessions()
    drop_database(sync_db_uri_test)
```

### 7.2 Per-Test Isolation with Rollback

```python
@pytest_asyncio.fixture
async def session(engine) -> AsyncGenerator[AsyncSession, None]:
    conn = await engine.connect()
    trans = await conn.begin()
    session = AsyncSession(bind=conn, expire_on_commit=False)
    try:
        yield session
    finally:
        await session.close()
        await trans.rollback()
        await conn.close()
```

```toml

```

## 9. Common Pitfalls

### 9.1 N+1 Queries

```python
# ❌ One SELECT per user
for user in users:
    print(user.messages)  # lazy load triggers each iteration

# ✅ Use selectinload
stmt = select(User).options(selectinload(User.messages))
```

### 9.2 `DetachedInstanceError`

```python
# ❌ Access after session close
async with session() as s:
    user = await s.get(User, 1)
print(user.name)  # DetachedInstanceError

# ✅ Use expire_on_commit=False and access inside context
```

### 9.3 JSONB Mutation Not Tracked

```python
# ❌ Silent no-op
user.config["key"] = "value"
await session.flush()

# ✅ Reassign
user.config = {**user.config, "key": "value"}
await session.flush()
```

### 9.4 Forgetting `await`

```python
session.flush()   # ❌ coroutine created but not awaited
await session.flush()  # ✅
```

### 9.5 `autogenerate` False Negatives

Does NOT detect: `server_default` changes, expression indexes, partial indexes, `CHECK` constraints from raw SQL, stored procedures, triggers. Always review generated migrations.
