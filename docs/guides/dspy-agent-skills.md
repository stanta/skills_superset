# DSPy-inspired Agent Skills: практическая навигация

Добавлены 12 самостоятельных, переносимых навыков для разработки и улучшения AI-компонентов. Это авторские рабочие процессы на основе идей DSPy, а не официальные upstream `SKILL.md`, не копия исходного кода и не установленная среда DSPy. Основные инструкции не требуют конкретного агентного хоста; применение библиотеки описано в локальных справочниках.

## Как агент находит навыки

Начальный поиск по-прежнему ограничен `skills/`. Основной вход — [meta-agent-systems](../../skills/meta-agent-systems/SKILL.md), затем его [каталог](../../skills/meta-agent-systems/references/members.md), затем полный `SKILL.md` выбранного атомарного навыка. Загружать все 12 одновременно не требуется: обычно достаточно 1–3 для текущей подзадачи.

Дополнительные маршруты: [meta-machine-learning](../../skills/meta-machine-learning/SKILL.md) для промптов, демонстраций, стоимости и экспериментального поиска архитектуры; [meta-testing-quality](../../skills/meta-testing-quality/SKILL.md) для оценки и регрессионного решения; [meta-research-knowledge](../../skills/meta-research-knowledge/SKILL.md) для больших корпусов и RAG. Точный ID ищется в [общем реестре](../../skills/meta-specialist-catalog/references/legacy-names.md). У каждого навыка не больше двух метакатегорий.

## Рабочая последовательность

`Контракт → оценка baseline → один целевой способ улучшения → независимый regression gate`

Сначала определить, что считается успехом и когда агент должен воздержаться от ответа. Затем зафиксировать данные, метрики, критические ошибки, разрешения и бюджет. Выбрать способ улучшения по реальному дефекту: примеры, промпт, retrieval, инструменты или структура программы. После выбора кандидата провести отдельную проверку на неиспользованном тестовом наборе. Самопроверка модели и высокий средний балл не заменяют эту процедуру.

`self-refinement` исправляет отдельный ответ во время выполнения. `prompt-optimizer` меняет переиспользуемую конфигурацию для будущих запросов. `few-shot-learning` не изменяет веса модели. `model-cost-optimizer` не обещает автоматического выбора самой дешёвой модели средствами DSPy. `ai-regression-gate` не является системой авторизации выпуска.

## Что лежит в каждом пакете

```text
atomic-skills/<id>/
  SKILL.md
  references/playbook.md
  evals/cases.json
  agents/openai.yaml
```

`SKILL.md` содержит условия применения, входы, процедуру, результат, проверки и ограничения. Справочник загружается только при необходимости и содержит соответствие DSPy и источники. `agents/openai.yaml` — необязательные интерфейсные метаданные для совместимых хостов, а не обязательный способ вызова. При отсутствии такого интерфейса достаточно обычного поиска и чтения.

Три сценария в каждом `evals/cases.json` проверяют полезное применение, отсутствие лишнего срабатывания и опасный/пограничный запрос. Это **спецификации 36 поведенческих проверок**, а не записанные успешные прогоны моделей. Для фактического сравнения использовать существующий [agent-evals-lab](../../atomic-skills/agent-evals-lab/SKILL.md), одинаковые разрешения, входы и бюджет; сохранять неудачные попытки и подтверждение загрузки навыка.

## Границы безопасности и совместимости

Оптимизатору нельзя менять тестовые ответы, оценщик, разрешения или критические правила. Train/validation отделены от test; после подбора по test нужен новый независимый набор. Общий бюджет включает вызовы учителя, судьи, reflection, повторы и вложенные модели. Данные отправляются только на разрешённые endpoints.

RLM/Flex требуют проверки установленной версии и реальной изоляции выполнения. Без безопасной среды использовать чтение/поиск или статические предложения, но не неограниченное локальное исполнение. Никаких production-ключей в поиске архитектуры, автоматического самодеплоя или повторных платежей ради улучшения ответа. Медицинские и иные критичные доменные правила остаются вне оптимизируемого модуля.

Существующие `prompt-engineer`, `rag-architect`, `agent-evals-lab`, `rlm-roec-context-reasoning`, `fine-tuning-expert` и MCP-навыки сохраняют свою область ответственности. Новые навыки ссылаются на них и не заменяют их содержимое.

## Проверки сопровождения

Из корня репозитория:

```sh
python -m unittest discover -s discovery -p 'test_*.py' -v
python discovery/validate_metaskills.py
```

Эти проверки не вызывают LLM и не тратят API-бюджет. Они проверяют пакеты, ссылки, реестр и маршруты, но не доказывают улучшение поведения агента. Существующий security-admission workflow дополнительно проверяет изменённые пакеты.
