# Building Fiction Timelines

## Core principle

Keep **publication order**, **diegetic chronology**, and **character-relative time** separate. Do not force false precision where the story only establishes a range.

## Event schema

Each event should have:

- event ID and title;
- branch / universe;
- start and end as exact value, range, or relative offset;
- certainty;
- location;
- participants;
- prerequisites and consequences;
- knowledge gained/lost;
- injuries, possessions, affiliations, relationship changes;
- source / issue / episode / chapter;
- publication date.

## Anchors and relative time

Choose a small set of anchor events and express uncertain events relative to them: “2–4 weeks after Event A” is better than an invented calendar date.

For long-running properties, explicitly choose one policy:

- real-time aging;
- compressed time;
- floating/sliding timeline;
- generational succession;
- explicit branching timelines.

## Temporal checks

Before locking an issue or episode, test:

- character ages and birthdays;
- travel and communication time;
- recovery, pregnancy, training, construction, research and political processes;
- technology or institution availability;
- cause before effect;
- who knows what, and when;
- simultaneous presence in incompatible locations;
- possession and custody;
- death, disappearance and return;
- branch divergence and merge logic.

## Branching

A branch must have:

- divergence event;
- parent branch;
- inherited canon snapshot;
- branch-specific changes;
- merge rule, if any.

Never use “alternate timeline” as a patch without recording the divergence.

## Output pattern

Maintain both:

1. a **machine-like event ledger** for checking;
2. a **human-readable chronology** for creators.

If prose and ledger disagree, resolve the ledger against canonical sources rather than silently editing history.

Use **governing-fiction-canon** for authority and **auditing-lore-continuity** for contradiction scans.
